# 365 AI Master v2：重新定位与产品方案

2026-10-23。Kenichi 要求从头重新定位、设计、开发，由 Claude Code 独立完成，不讨论细节。本文是这一轮的单一依据：先框定，再定位，再定设计，最后是验收标准。决策逐条记在 `decision-trail.tsv`。

## 一、框定

**完成判据（可证伪）**

1. `swift test` 全部通过；`pytest` 结果不比改动前差（713 passed）。
2. 渲染工具 `scripts/render_v2.sh` 用真实快照出全部页面（首次引导、首页、今日一招三种状态、维度详情、修炼路线、发现、周报、付费页、设置、分享卡），中英 × 浅深色，人工逐张检查无截断、无重叠、无空白页。
3. 五秒测试：首页首屏不滚动就能回答三件事：我什么水平、今天做什么（有一个主按钮）、这周用得怎么样。
4. 打包后的真 App 能启动，菜单栏显示分数，点开就是新首页（真机截图）。
5. 官网 `site/` 中英两版在 1440 和 390 宽度下无横向滚动、深浅色都正常（浏览器截图）。
6. 宣传素材 `marketing.md` 覆盖全部发布渠道。

**范围**：重写全部用户可见界面（约 20 个 Swift 文件）、新设计系统、替换旧界面测试；新建官网与宣传素材。引擎、排名服务、激活码、抓取流水线、付款通道都保留不动，它们是好的，问题出在呈现。

**不做**：不部署、不推送、不上架、不发帖。正式分发需要 Apple 开发者签名，付款需要 Waffo 商户上线，这两件事等 Kenichi。

## 二、诊断：现在为什么不好用

看了四个页面的截图和引擎真实数据（分数 69，本周 AI 用量折算约 $1,310，Codex 周额度用了 54%，24 张技能卡亮了 12 张，连续 30 天有使用记录）。数据很足，问题全在呈现：

1. **没有主线**。三个页签是三套心智：「我」是成绩单，「大师推荐」是信息流，「修炼」是小游戏。用户打开不知道先干什么。
2. **四套等级互相打架**。首页写「AI 熟练者」，引擎的新手村写「AI 探索者」，修炼页写「Lv.3 学徒」，还有一个 B 级。
3. **两个连续天数互相矛盾**。日志里真实连续使用 30 天，修炼页却写「连签 0 天」。
4. **游戏化不和真实行为挂钩**。「打卡 +5 XP」点一下就加分，和会不会用 AI 无关；「新手村 2/9、图鉴 12/24、徽章 6」三个数字没有解释。
5. **最有价值的数字藏在页脚**。「本周用量折算 $1,258、Codex 额度 50%」挤在一行小字里，还被截断。
6. **榜单只有仓库名**。servers、dspy、mem0 这样的名字对新手没有意义，也没有「为什么值得装」。
7. **付费页没讲清买到什么**。四条三角形列表，选项边框被裁掉，下面一大片空白。
8. **术语太多**：模型路由、上下文卫生、沉淀复用、图鉴、新手村。

## 三、调研：从最好的小工具借什么

额度监控已经是免费品类：CodexBar（MIT，2.2 万星）、ClaudeBar、Claude Usage Tracker 都免费，收费的 Usagebar 是 $9 一次性买断。所以额度只能做基础显示，付费点必须是别人没有的东西：**一个读得懂你日志的 AI 教练**。

| 产品 | 借鉴的做法 | 落到 365 |
|---|---|---|
| Oura / Whoop | 一个总分 + 几个贡献项 + 每天一条建议，贡献项按状态着色 | 首页一个分数；四个维度按「优秀 / 良好 / 待提升」着色，不再按维度乱配色 |
| Apple 健身圆环 | 每天一个可完成的环，里程碑奖章 | 今日一招完成就合环；连续 7/30/100/365 天是唯一的奖章 |
| Duolingo | 一条路线、分单元，今天的那一课最显眼；价值时刻之后再出付费墙 | 修炼路线分入门/进阶/高手；入门免费，进阶和高手是 Pro |
| CodexBar | 菜单栏小仪表、重置倒计时、按速度提示够不够用 | 额度行显示「还剩 46% · 4 天后重置 · 按现在的速度够用」 |
| Things 3 / Dato | 克制、留白、「今天」作为默认视图 | 首页就是「今天」，不设页签 |
| Flighty | 状态先行，倒计时和状态标签一眼可读 | 每个卡片先给结论，再给数字 |
| Raycast / iStat Menus | 免费核心 + Pro；完整试用；隐私本身就是品质 | 14 天完整试用、不绑卡；「0 token、不上传」放在显眼处 |
| Spotify Wrapped / Strava | 可分享的个人故事卡 | 分享卡只讲段位和学会了什么，不炫耀 token 消耗 |
| 付费墙研究（RevenueCat、Adapty 2026） | 价值时刻之后出付费墙，试用开启率约 2.1 倍；试用页文字要少 | 付费入口放在「入门路线学完」和「点开锁住的卡」这两个时刻 |

来源：[CodexBar](https://github.com/steipete/CodexBar)、[Claude 用量工具对比](https://sessionwatcher.com/guides/best-claude-code-usage-trackers)、[Adapty 2026 付费墙](https://adapty.io/blog/high-performing-paywall-2026/)、既有调研 `我的商业版图/365-AI-Master-产品设计调研与方案-2026-10-21.md`。

## 四、重新定位

- **一句话**：每天一招，365 天成为 AI 大师。
- **英文**：One AI skill a day. Master AI in 365 days.
- **它是什么**：住在 Mac 菜单栏里的 AI 教练，给每天用 Claude Code、Codex 的开发者和创业者。
- **三个承诺**：
  1. 看清你的 AI 水平：一个分数、一个段位，和全球用户比。
  2. 每天学一招：从你自己的日志里挑你还没用过的技巧，用一次就自动点亮。
  3. 看清这周用了多少：按公开价格折算的用量，和额度还剩多少、几天后重置。
- **信任底线**：全部在本机计算，不调用任何 AI，0 token，不上传使用记录。
- **名字终于讲得通**：365 = 一年 365 天，每天一招；$12/年 = 每月 $1。

## 五、一个段位体系

全产品只保留一套段位，按分数：

| 分数 | 段位 | English |
|---|---|---|
| 0–39 | 新手 | Novice |
| 40–59 | 学徒 | Apprentice |
| 60–74 | 熟练者 | Practitioner |
| 75–89 | 专家 | Expert |
| 90–100 | 大师 | Master |

首页显示「再提 6 分升到专家」，给出明确的下一个目标。引擎的新手村称号、修炼等级、XP、宝箱、护盾、手动打卡在界面上全部不再出现（引擎照常计算，不删数据）。

连续天数只用一个：日志里真实的连续使用天数。

## 六、信息架构

不设页签。打开就是「今天」，从上到下回答三个问题，其余内容点进去看。

│      再提 6 分升到专家                 │

## 七、核心循环

1. 菜单栏显示分数；今天的一招还没完成时，分数旁有一个小金点。
2. 打开看到「今日一招」，点「复制提示词」，去 Claude Code 或 Codex 里用一次。
3. 下次刷新时，引擎在日志里看到你用了，卡片自动点亮，今天的环合上。日志看不出来的技巧（共 9 个），由你点「我学会了」。
4. 每周一出周报（Pro）：分数变化、学会了什么、下周练什么。

## 九、设计系统

- **气质**：安静、精致、有段位感。品牌色是 Kenichi 选定的大师金，其余全部让位。
- **颜色**：浅色暖白底 `#F7F5F0`、白卡片、墨色字 `#1B1916`；深色夜蓝底 `#0F131A`、卡片 `#181D26`。金色只用在分数、主按钮、段位和 Pro。状态色：优秀青绿、良好金、待提升珊瑚。
- **字体**：数字和标题用 SF Pro Rounded（圆润、像健身记录），正文 SF Pro / 苹方。字号只用五档：44 / 20 / 15 / 13 / 11。
- **布局**：弹窗 400 × 680，16pt 外边距，卡片圆角 16，卡片之间 12。每张卡片先给结论再给数字。
- **动效**：分数数字滚动、环形进度、卡片状态切换 0.2 秒；尊重系统「减少动态效果」。
- **图标**：统一用 SF Symbols。

## 十、执行顺序

1. 先搭验收工具：渲染脚本 + 真实数据夹具，旧界面截图作为基线。
2. 三版首页原型并排比较，选定一版。
3. 删除旧界面和旧界面测试（先减后加）。
4. 按顺序重建：设计系统 → 弹窗外壳与导航 → 首页 → 今日一招 → 维度详情 → 修炼路线 → 发现 → 周报 → 付费页 → 设置 → 首次引导 → 分享卡 → 菜单栏图标。每做完一块就渲染检查。
5. 全量测试、打包、真机截图。
6. 官网（中英）与宣传素材。
